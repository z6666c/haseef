# تشغيل حصيف على خادم حقيقي

هذا الدليل ينقل المنصة من نسخة العرض (GitHub Pages ببيانات وهمية) إلى تشغيل فعلي بقاعدة بيانات حقيقية،
على خادم واحد داخل المملكة. كل الملفات في مجلد `deploy/`، وتُختبر تلقائياً في
`.github/workflows/deploy-check.yml` بتشغيل المنصة كاملة عند كل تعديل عليها.

## ما تحتاجه قبل البدء

| المتطلب | التفاصيل |
|---|---|
| خادم داخل المملكة | Ubuntu 22.04 أو 24.04، بحد أدنى 4 أنوية و8 جيجابايت ذاكرة و80 جيجابايت تخزين SSD. مزوّد سحابي بمنطقة سعودية معتمدة لدى الهيئة الوطنية للأمن السيبراني. |
| النطاق | `haseef.sa` مع إمكانية إضافة سجلات DNS. |
| بريد للشهادات | مثل `ops@haseef.sa`، تصله تنبيهات Let's Encrypt. |
| (اختياري) تخزين كائنات | متوافق مع S3 داخل المملكة، لنسخة احتياطية خارج الخادم. |

## البنية

```
الإنترنت ─► Caddy :443 (شهادات تلقائية، ترويسات أمان)
              ├─ app.haseef.sa    ─► client  (Next.js)    /api/* ─► api
              ├─ admin.haseef.sa  ─► admin   (Next.js)    /api/* ─► api   (يمكن حصره بعناوين IP)
              └─ haseef.sa        ─► تحويل إلى app.haseef.sa/welcome
            api (FastAPI) ─► db (PostgreSQL 16 + RLS)
            worker + beat (Celery) ─► redis       — التنبيهات وتحديث المؤشر ليلاً
```

قاعدة البيانات وRedis على شبكة داخلية بلا منافذ خارجية. الواجهات لا تخرج للإنترنت. الخادم والعمّال يخرجون فقط
لمزوّد الواتساب والبريد.

## خطوات النشر الأول

1. **تجهيز الخادم** (مرة واحدة):
   ```bash
   curl -fsSL https://raw.githubusercontent.com/z6666c/haseef/main/deploy/scripts/bootstrap.sh | sudo bash
   ```
   يثبّت Docker وجدار الحماية (22 و80 و443 فقط) والتحديثات الأمنية التلقائية وfail2ban، وينسخ المستودع إلى
   `/opt/haseef`، وينشئ `deploy/.env` بأسرار عشوائية، ويجدول النسخ الاحتياطي اليومي 3:30 فجراً.

2. **DNS**: سجلات A لـ `haseef.sa` و`www` و`app` و`admin` إلى عنوان الخادم. انتظر انتشارها قبل الخطوة 4
   حتى تصدر الشهادات.

3. **المتغيرات**: راجع `/opt/haseef/deploy/.env` (النطاق، البريد، وحصر غرفة العمليات بـ `ADMIN_ALLOW_IPS` إن رغبت).
   الأسرار مولّدة ولا تُنسخ لأي مكان آخر. احفظ نسخة منها في مدير كلمات مرور الشركة.

4. **النشر**:
   ```bash
   sudo /opt/haseef/deploy/scripts/deploy.sh
   ```

5. **أول مدير عام**:
   ```bash
   sudo /opt/haseef/deploy/scripts/create-admin.sh ops@haseef.sa "اسم المدير"
   ```
   تظهر كلمة مرور مؤقتة مرة واحدة، ويُطلب تغييرها عند أول دخول على `https://admin.haseef.sa`.
   بعدها يُضاف بقية الفريق والأدوار من غرفة العمليات نفسها.

## التحديث

```bash
sudo /opt/haseef/deploy/scripts/deploy.sh
```
يسحب آخر نسخة من `main`، يبني الصور، يأخذ نسخة احتياطية، يطبّق تحديثات قاعدة البيانات والمحتوى المرجعي،
ثم يعيد تشغيل الخدمات ويتحقق من الصحة. تحديثات قاعدة البيانات لا تُطبَّق تلقائياً عند تشغيل الخادم في الإنتاج؛
تُطبَّق في هذه الخطوة فقط.

## النسخ الاحتياطي والاستعادة

* يومياً 3:30 فجراً: `deploy/backups/haseef-db-*.dump` وملفات المكتبة، وتُحذف بعد `BACKUP_KEEP_DAYS` (14 يوماً).
* بضبط `BACKUP_S3_*` تُرفع نسخة قاعدة البيانات أيضاً إلى تخزين خارج الخادم.
* يدوياً: `deploy/scripts/backup.sh`
* الاستعادة: `deploy/scripts/restore.sh deploy/backups/<الملف>` (يأخذ نسخة من الوضع الحالي أولاً ويطلب تأكيداً).
* **اختبر الاستعادة مرة كل شهر** على خادم تجريبي؛ النسخة التي لم تُجرَّب استعادتها لا يُعتمد عليها.

## الأمن المطبّق

* HTTPS إلزامي مع HSTS، وترويسات CSP ومنع التضمين في إطارات.
* RLS في قاعدة البيانات: الخادم يتصل بدور لا يتجاوز العزل، وكلمات مرور الأدوار تُضبط من `.env` عند كل إصدار.
* إيقاف الدخول 15 دقيقة بعد 10 محاولات فاشلة للبريد نفسه، وكل محاولة فاشلة في سجل التدقيق.
* الحاويات تعمل بمستخدمين غير جذريين، والسجلات محدودة الحجم.
* توثيق `/docs` للواجهة البرمجية معطّل في الإنتاج.

## أوامر مفيدة

```bash
cd /opt/haseef/deploy
docker compose -f docker-compose.prod.yml ps              # حالة الخدمات

```

## الدفع الإلكتروني والبريد وبوت الموظفين (الإصدار 0017)

| الميزة | الإعداد في `deploy/.env` | ملاحظات |
|---|---|---|
| الدفع الإلكتروني (ميسّر) | `HASEEF_PAYMENT_PROVIDER=moyasar` و`HASEEF_MOYASAR_SECRET_KEY` | سجّل عنوان الإشعارات في لوحة ميسّر: `https://app.<النطاق>/api/v1/payments/moyasar/callback`. حصيف لا يعتمد الإشعار بل يسأل ميسّر عن الحالة والمبلغ قبل اعتماد الدفع. بدون مفتاح يبقى الدفع الإلكتروني متوقفاً (رسالة للعميل) وتسجّل المحاسبة الدفعات يدوياً. |
| البريد | `HASEEF_EMAIL_PROVIDER=smtp` و`HASEEF_SMTP_*` | لتفعيل البريد ورسائل التحقق والإيصالات والتنبيهات بالبريد. |
| بوت الموظفين | `HASEEF_WHATSAPP_PROVIDER=meta` و`HASEEF_META_VERIFY_TOKEN` و`HASEEF_META_APP_SECRET` | عنوان الويبهوك: `https://app.<النطاق>/api/v1/webhooks/whatsapp` (حقل messages). التوقيع إلزامي في الإنتاج. |
| التسجيل الذاتي | `HASEEF_SIGNUP_ENABLED=true` | حد 5 تسجيلات لكل عنوان في الساعة. أوقفه بـ `false` إن أردت التجارب بطلب فقط. |
| التسعير | من غرفة العمليات ← «التسعير» | أسعار الباقات والإضافات وحصص الرسائل، دون إعادة نشر. |

قوالب واتساب الجديدة للتقديم إلى Meta: `haseef_tax_due` و`haseef_bot_invite` (التفاصيل في `docs/whatsapp-templates.md`).
